# August 28, 2026

## What's new

- **Resource monitoring.** A new Resources page shows live CPU, RAM, and disk for the server and for each of IoTStack's three services, plus history by day, week, month, and year. Configurable warn/critical thresholds show a heads-up on Overview before you're caught off guard. A small agent runs directly on the host (installed automatically) to see real host-level usage, since the app's own containers can't.
- **Control panels.** Every device now gets a Control page — bind a widget to a real telemetry or status field (a sensor reading, a relay switch) and view/operate the device without reading raw JSON. Configure controls inline via Edit mode on the device's own Control page.
- **Fixed:** a control could show a stale value when two messages arrived within the same second — message order now breaks ties by id, not just timestamp.
- **Quick Start sample projects, always secure MQTT.** A new "Try a sample project" wizard on Overview goes from zero to a real device with matching controls and ready-to-flash code in a few clicks. Generated Arduino code — from this wizard and the per-device code generator — now always connects over MQTTS (TLS), never plain MQTT.
- **Cleaner names for Quick Start devices.** A device created from a template is now named `<Template name> - <Board name>` in your dashboard's own language, with an auto-incrementing suffix (`- 001`, `- 002`, …) if that name is already taken.
- **Device online status on the Control page.** Shows a live "Online · Ns/phút/giờ/ngày trước" indicator based on the device's last message, updating on its own without a page reload.
- **Tighter MQTT topic & ACL model.** A new `event` topic joins telemetry/status/ping for device lifecycle messages (boot, etc). Every device's role now grants only the exact publish/subscribe rights its job needs, instead of one combined wildcard — a device can no longer publish a fake command to itself or read back its own sensor topics. The collector, command-publisher, and Dynamic Security admin are now three separate MQTT accounts instead of one shared one. Commands sent to a device now carry a `request_id` for correlation. Every message is also bounded by size, key count, and nesting depth.
- **Last Will and Testament.** Generated firmware now registers a real MQTT will, so an ungraceful disconnect (network/power loss) still produces a `network.disconnected` event instead of silence.
- **Control Panel "latest event" widget.** A new control type shows the most recent lifecycle event for a device (optionally filtered to one type), with a relative-time stamp — same reuse as the online-status indicator.
- **Firmware now reports its state right after boot, and pings on a schedule.** Every generated sample and the Quick Start template publish a `status` right after the boot `event`, and send a periodic `ping` regardless of which sample — previously only one sample did.
